# Anonymizer — Reference Implementation

> **NEVER commit production data dumps to this repository.**
> This directory contains a reference implementation showing how production-like data
> **would be** transformed into synthetic fixtures. It is NOT a pipeline — no production
> data enters this repository under any circumstances.

## Purpose

`scrub.ts` demonstrates the transformation logic that would be applied if production
data were ever needed as a starting point for test fixtures. In practice:

1. All fixtures are generated by Faker with a fixed seed (see `generators/`).
2. No production database is connected to this repository.
3. No production data is exported, copied, or transferred here.

## When this would be used

If a real-world edge case cannot be reproduced with Faker-generated data, the process is:

1. Export the minimal relevant rows from production (with DPO approval).
2. Run `scrub.ts` to replace all personal data with synthetic equivalents.
3. Validate the output with `validator/validate.ts` (PII heuristics must pass).
4. Commit only the scrubbed output, never the original.
5. Delete the original immediately after scrubbing.

## Controls

- **PII heuristic validator** (`validator/validate.ts`) hard-fails on any real data pattern.
- **TruffleHog** scans for secrets in every CI job.
- **PR checklist** requires "No new PII in fixtures" confirmation.
- **DPIA-QA-000** documents the synthetic-only policy.
