### 2. Necessity and proportionality

This repository exists to hold test automation assets. The synthetic-only policy is the
primary control: no production data enters this repository under any circumstances.

The PII heuristic validator (`fixtures/validator/validate.ts`) provides a secondary
control — it scans every fixture file for patterns that match real Lithuanian personal
data (personal code format, phone number ranges, real email domains) and hard-fails CI
if any match is found.

### 3. Risks identified

| Risk                                              | Likelihood | Impact | Mitigation                                                                                                              |
| ------------------------------------------------- | ---------- | ------ | ----------------------------------------------------------------------------------------------------------------------- |
| Production data accidentally committed as fixture | Low        | High   | PII heuristic validator in CI; `.gitignore` covers `.env*`; PR checklist requires "No new PII in fixtures" confirmation |
| Stripe test-mode keys in webhook fixtures         | Low        | Medium | Validator scans for `sk_live_`/`pk_live_` patterns; `reset.sh` pattern from viavitae-demos applied here                 |
| Keycloak test credentials leaked                  | Low        | Medium | Test realm completely isolated from production; credentials from GitHub Environments only                               |

### 4. Controls

1. **Synthetic-only policy.** All fixture data generated by Faker with fixed seed.
2. **PII heuristic validator.** Runs in every CI job; hard-fails on match.
3. **PR checklist.** "No new PII in fixtures" box must be checked or annotated "n/a".
4. **Secret scanning.** TruffleHog `--only-verified` over full history.
5. **Annual review.** This DPIA is reviewed annually and after any fixture schema change.

### 5. Conclusion

**No personal data is processed.** This DPIA confirms the synthetic-only policy and
documents the controls that enforce it. If the scope of this repository changes to include
any real data (even anonymised), a new DPIA must be completed **before** processing begins,
per rule R5.
